=========================================================
PROPOSED CHANGES: THE MULTIMODAL DIAGRAM READER
=========================================================

1. THE GOAL WE ARE SOLVING:
---------------------------------------------------------
Currently, our AI backend only extracts and reads text and tables.
Because electronics engineers rely heavily on schematic diagrams, 
graphs, and pinouts, we want the AI to be able to "look" at the 
diagrams in the datasheet, explain them to the user, and physically 
show the image to the user in the chat interface. 
This will elevate the backend to an enterprise-grade "Vision" tool.

2. HOW IT WILL WORK (THE MAGIC TRICK):
---------------------------------------------------------
Because FAISS (our math database) cannot easily compare text to raw PNG 
files, we will use a clever architecture:
A. Extraction: When you upload a PDF, the backend will rip out all the 
   images and save them to `storage/images/doc_ID/`.
B. Pre-Reading: During the upload process, the backend will silently 
   send every image to Gemini 3.1 Vision and ask: "Describe this 
   electronics diagram in extreme detail."
C. Vectorizing: We will save Gemini's text description of the image into 
   our SQLite and FAISS databases, linked directly to the image file path.
D. The Chat: When you ask "Explain the pinout diagram", FAISS will easily 
   find the math for the text description. The backend will grab the 
   original PNG, convert it to Base64 code, and send both your question 
   and the image back to Gemini to answer!

3. SHOWING THE IMAGE TO THE USER:
---------------------------------------------------------
We want the frontend to display the actual diagram.
We will update our FastAPI server to "mount" the `storage/images/` 
folder as a static directory.
We will add an `image_url` field to our `ChatResponse` schema.
If the AI uses an image to answer your question, the backend will return 
a URL (e.g., `http://localhost:8000/images/doc_42/pinout.png`). 
Your frontend friend can simply use an <img src="..."> tag to show it!

4. THE EXACT CODE CHANGES REQUIRED:
---------------------------------------------------------
[Change 1]: `database/models.py`
Add a new `DocumentImage` table to track image paths. Add an `image_id` 
column to our existing `document_chunks` table.

[Change 2]: `database/crud.py`
Add database functions to save and retrieve images.

[Change 3]: `schemas/chat_schema.py`
Add `image_url: Optional[str] = None` to the `Citation` schema.

[Change 4]: `main.py`
Add `app.mount("/images", StaticFiles(directory="storage/images"))` 
so the images are publicly accessible via web URLs.

[Change 5]: `services/pdf_service.py`
Modify it to save the extracted images, ask Gemini for descriptions, 
and insert those descriptions into our database as chunks.

[Change 6]: `services/rag_service.py`
Modify `_ask_gemini` to support multimodal (Vision) payloads. If a 
retrieved chunk is an image, convert the .png to Base64 and send it 
in the JSON request to Google.
