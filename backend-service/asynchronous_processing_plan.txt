=========================================================
PROPOSED CHANGES: ASYNCHRONOUS MULTIMODAL PROCESSING
=========================================================

1. THE GOAL WE ARE SOLVING:
---------------------------------------------------------
Currently, uploading a document takes 4 to 5 minutes because 
the backend pauses to respect Google's free tier API limits 
while processing the 50+ images. We want the user to be able 
to start asking text-based questions immediately, while the 
images process silently in the background.

2. HOW IT WILL WORK (LAZY LOADING & WEBSOCKETS):
---------------------------------------------------------
A. Text Phase (Instant): The backend extracts all text, 
   generates text embeddings, and saves them in 10 seconds.
   The document is marked "Text Ready".
B. The Chat: The user can start chatting instantly with the 
   text data!
C. Image Phase (Background): The backend begins processing 
   the images one-by-one, pausing for 4.5 seconds between 
   each to respect the 15 RPM limit.
D. Live Progress: We will use a WebSocket connection to stream 
   live updates to the frontend (e.g., "Learning diagram 1 of 53...").

3. THE EXACT CODE CHANGES REQUIRED:
---------------------------------------------------------
[Change 1]: `services/websocket_manager.py`
Create a central manager to handle real-time streaming connections.

[Change 2]: `services/pdf_service.py`
Split `process_document` into `process_text_and_tables` and 
`process_images_incrementally`.

[Change 3]: `services/embedding_service.py`
Modify it to embed specific new chunk IDs instead of fetching 
the entire document's chunks at once.

[Change 4]: `api/upload.py`
Create a new `@router.websocket("/ws/{document_id}")` endpoint.
Refactor the background task to call the Text Phase, update the 
status to `text_ready`, stream the WebSocket message, and then 
start the Image Phase.

[User Action Required]:
Your frontend developer will need to update their code to connect 
to the new WebSocket endpoint to show the live progress messages.
